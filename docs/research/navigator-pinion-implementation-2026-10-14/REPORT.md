# Navigator pinion option — local implementation and replay

Implemented locally in `${PRIVATE_CACHE}` on `codex/navigator-pinion-option`. Openpilot commit `97f050c79`; opendbc commit `54f25cd4`. Portable patches accompany this report. No push, deployment, device parameter write, restart, firmware flash, or active ECU query was performed.

## Behavior

Persistent `FordPrefSteerAngleCurvature` defaults OFF. UI permits changes only offroad for the Expedition CANFD configuration used by this Navigator. The next onroad initialization applies paired Python and Panda flags before constructing the controller. Fixed geometry must match the safety model. Invalid/missing/stale pinion feedback fails closed. Navigator factors remain **1.20/0.97**. Steering limits were not widened.

## Verification

- 173 targeted Python/native Ford tests passed; 77 skipped; 12,000 subtests passed.
- Three UI contract tests passed. These extract the actual predicate/callback; full graphical layout, lock refresh, native Params binding, and card startup were not exercised. Wiring was independently reviewed.
- Changed production Python and new Ford tests passed Ruff. The existing lateral-angle test contains a pre-existing unused `patch` import; that baseline finding remains. Diff whitespace checks passed.
- Independent review found no important/critical issues.
- Full chronological replay of 45 saved rlog segments across three drives: **252,406 controller updates, 10,082,330 received physical CAN frames, 148,765 accepted generated transmissions, 14,475 active angle frames, zero pinion-mode TX rejections, zero checked RX invalid frames**.
- OFF mode generated byte-identical CAN streams to the exact preserved live steering source on every drive. OFF and preserved baseline both encountered the same single angle rejection at 23.43 mph in the earlier drive; the option introduced no OFF regression.
- Replaying recorded original sendcan separately produced one angle rejection while controls_allowed was false and 14 button rejections. Recorded blocked counters are cumulative and cannot be equated with reconstructed replay counts.
- Each drive has one initial RX warmup invalid tick. Generated messages before the first recorded Ford safety configuration were explicitly excluded: 369/371/369 respectively. No controls_allowed override was used.

See `*-replay.json`, `full_replay.py`, and console logs for inspectable evidence. The replay uses the actual controller and compiled native safety hooks, including all generated TX message types and physical RX traffic. It does not reproduce the forwarding hook or the complete Panda firmware/hardware environment. macOS rejected sanitizer library loading; native safety tests/replay used a plain debug C build. This is recorded-input, open-loop verification, not closed-loop vehicle simulation or road validation.

## What the percentages mean

The prior 77–80% result is reduction in median yaw-rate-equivalent estimation error against calibrated Comma motion at 20–30 mph. The approximately 5% result is the proportion of low-speed steering commands changed when the same saved controller inputs were held fixed. They measure different things. Correcting feedback changes commands mainly when the feedback-based deviation clamp binds. The strongest tight understeer example had no meaningful command correction; the gentle example had a small correction. Therefore the option addresses the measured feedback bias but is not demonstrated to cure the low-speed understeer/wandering. No handling-improvement percentage is established.

## Deployment boundary

Remain local for review. Deployment would require the matching openpilot, opendbc and Panda safety build together, plus device-build validation. Do not enable the Python option with old Panda firmware. No deployment is authorized in this task.
