## Network inference and important limit

Prior recording analysis found genuine0x461 at bus0 plus transmitted-forwarded copies bus130 (=physical2 +128). Taken with source mapping, this supports **vehicle/main-side source -> Panda -> camera-side forwarded copy**. It does not establish the source module's physical original bus, gateway ingress policy, intended recipient, or whether GWM is merely mirroring an already consumed button input.

A camera harness splits the camera connection. It cannot stop the original transmitter delivering frames to another receiver already on the same vehicle-side segment. Dropping Panda's0->2 forwarding only removes the camera-side copy, not bus0 originals. Consequently a clean replacement strategy depends on locating the consumer relative to that split. If PCM consumes the request before/elsewhere than camera, camera-side suppression cannot solve competing publishers. If a gateway ignores reflected messages or only routes the signal in one direction, bus0 injection might be visible but ineffective.

Neither source inspection nor passive capture can prove ECU acceptance. The code lacks the receiver implementation and the gateway routing table for this vehicle. Required missing evidence: VIN-specific switch->module->GWM->PCM wiring/routing, and eventually an explicitly authorized bench/stationary injected press/release with independent status feedback. Current authorization excludes that active test. It is incorrect to claim this read-only work demonstrates an injectable command.
