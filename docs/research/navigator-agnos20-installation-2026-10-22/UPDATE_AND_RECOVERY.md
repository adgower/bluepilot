## Authorized execution, before reboot

1. Obtain the final explicit OS-write decision covering inactive slot A boot/system, boot-slot selection and reboot. Freshly confirm parked/ignition off, physical access, stable power, Wi-Fi and recovery cables. Rerun `final_preparation.py`; compare current source and owner settings to backup. Do not infer physical power readiness from uptime alone.
2. Write an authorization record with exact parent/child/from/to/old/target fields required by `transition_guards.require_authorization` and `physical_presence_and_stable_power_confirmed: true`. No such record is created during preparation.
3. Preserve `/data/continue.sh` metadata and bytes in the private backup. Install the exact maintenance hold defined by `os_update_runner.HOLD` atomically, owned by comma, with the original executable mode. Stop `comma.service`; verify it is inactive and its manager/firmware worker processes have exited. Check the hold again. Keep it across every reboot until matching source and native validation pass. This prevents the old source's launcher from requesting its old OS or starting firmware processes on AGNOS 20.
4. Run the staged `os_update_runner.py STAGE` without `--execute` as root for a fresh **read-only** full check. `--verify` on the official CLI is mutating and is not used as an inventory command.
5. Run `os_update_runner.py STAGE --execute` in a detached, logged transient systemd service with a finite runtime limit, low CPU/IO priority and sufficient memory for the official sparse decoder. It refuses execution without the exact authorization record, original live source, AGNOS19.9/B/offroad, unchanged candidate hashes, verified Mac backup, fresh-source receipt and installed maintenance hold/inactive runtime.
6. The pinned official updater marks only A unbootable, writes boot/system from verified local cache, fully hashes all seven target images and then selects A using its supported swap operation. A verification failure never selects A. `os-written-awaiting-reboot.json` must exist and the service must have exit status zero before proceeding. The runner does not reboot, change source or restore runtime.
7. Retain logs and verify original slot B was not written. If anything fails, keep runtime held and remain on B; do not blindly rerun or launch either source. After successful receipt and target verification, explicitly reboot. SSH loss during that reboot is expected; it does not authorize a source-only rollback.

## After reboot, runtime remains held

1. Reconnect and verify maintenance hold bytes before changing service state. The enabled oneshot `comma.service` may be active after reboot while running only the hold; stopping it before reboot does not persist. After verifying the hold, stop that service and require it inactive. Then verify `/VERSION` is 20, `abctl --boot_slot` is `_a`, owner settings/calibration remain preserved, and root filesystem and storage are healthy. Record uptime. If any of these differ, stop. Mark boot successful with `sudo abctl --set_success` only after these checks.
2. With runtime still held, move the complete old `/data/openpilot` tree to the recorded rollback destination, then move the pristine candidate to `/data/openpilot`. Check exact parent/child and independent Git objects at the final path. If the second move fails, retain the hold and restore the old path without launching it on OS20. Retain the matching old OS slot for recovery.
3. Build **all native targets from pristine state on AGNOS20 at the final path**, as comma; use a detached logged `scons -j1` build. Use fresh private SCons/cache state. The prebuilt marker must be absent throughout build and validation; no copied AGNOS19.9 host outputs or Mac artifacts are permitted. Check AGNOS20 compiler/tool availability first; an unavailable `cc` alias is a toolchain integration blocker, not grounds to reuse old binaries.
4. Run native Ford/safety/tracking tests and Card/context/pipeline/scheduler/parent startup checks with private Params/cache, a mount and network namespace, USB/SPI/GPIO/serial vehicle interfaces masked and no privileges. The prepared `isolate20.sh` / `inside20.py` harness uses the exact new stage and final source path; do not run the old hardcoded `21325dccb` harness. Launch each probe/build/replay phase via `unshare --mount --net --fork bash STAGE/isolate20.sh STAGE PHASE` in the dedicated `navigator-agnos20-native.service` transient unit. Its source mount is writable only for build and readonly for test phases; private Params/cache and blocked devices apply throughout. These adaptations are syntax-checked only until AGNOS20 can run them. Keep its isolation probes and fresh AGNOS20 build receipts. Neither manager nor hardwared/pandad is started inside offline validation. A harness adaptation failure is a stop condition, not a waiver.
5. A full build embeds the new parent revision in its generated Panda firmware. Preserve that newly built image as evidence, then restore the exact backed-up `panda_h7.bin.signed` after host build/offline validation and verify its hash against the unchanged live baseline. Verify unchanged Panda safety/transport sources and Chestnut version expectation. Seal the completed AGNOS20 host build with a full native-output hash manifest and only then create the standard `prebuilt` marker, so ordinary startup cannot rebuild and replace the preserved Panda image. This marker records a completed, validated build; it is never present to skip the required fresh build/tests. Its cost is that future source changes require a new explicit build and reseal before activation; app updates remain paused. Recheck every owner preference and calibration hash. Restore the exact original `/data/continue.sh` only after build/offline acceptance passes, then start `comma.service`.
6. Perform offroad runtime acceptance: exact live pair, valid required processes/topics, no unexpected alerts/stopped processes, preserved settings and passive no-output state. Request ignition on, stationary in Park, assistance disengaged for passive powered acceptance. This is not road-performance proof.

## Rollback while SSH remains usable

Always install/verify the maintenance hold and stop runtime first. If new source has been activated, preserve it under a distinct candidate-failed path and restore the complete original source tree to `/data/openpilot`. Do **not** run its old launcher on OS20. Verify the saved 19.9 slot-B hashes, then `sudo abctl --set_active 1`, checking command success. Keep the hold and explicitly reboot. After reconnect, require AGNOS19.9, slot B, exact old source pair, preserved owner settings and matching firmware before restoring original launcher/startup. If SSH or boot is unavailable, use physical recovery. Source restoration alone is not OS recovery.
