# Joint allocation and integral response: proposed local experiment

Status: design for parent/reviewer review; no implementation yet. Paired source, Comma and 1.20/0.97 remain unchanged. This is an offline response-state experiment, not an installation candidate.

## Problem and existing evidence

The current producer integrates target-minus-measured acceleration. The consumer selects brake bits from raw demand plus effective pitch, then may release a nominal brake after +0.02 net/raw intent persists for 60 ms, despite the nominal +0.3 release threshold. Pressure clearance and the propulsion ramp subsequently limit usable authority. Their returned feedback freezes positive integration, but that predicate is not a dynamic description of achieved acceleration. Weak coast-account changes cannot address most full-brake cycles: the prior 316-segment candidate never activated, and 1,600/1,614 selected weak positive-intent full-brake callbacks already had a locked account.

The prior gear/grade investigation already supplies settled net-response fits and 277 release episodes. Net-command held-out RMSE .0849 beat request plus/minus gravity .2026/.1433. It supplies no qualified Alpha inactive-propulsion/no-brake windows and no strict isolated coast steps. Its valid-propulsion bridge increased 992→1,008 edges and weakened 430 later strong requests after fallback. Preserving the PID algorithm without preserving the authority trajectory did not preserve later braking.

Therefore this experiment must distinguish three quantities: desired net acceleration, valid numerical actuator request, and observed achieved acceleration. Inactive propulsion −5 is a protocol sentinel, never an achieved acceleration estimate.

## Alternatives considered

1. Expand weak-entry allowances, reopen spent debt or alter release thresholds: rejected. It hides the same blocker and either enlarges deferral or increases braking exposure.
2. Fit another gear/grade table and repeat the valid-propulsion bridge with the existing integral feedback: rejected. Prior observations and later strong-braking divergence already disprove that as a sufficient design.
3. Explicit response/authority state plus causal integral tracking, with unsupported physical regimes represented as unknown: proposed. First test its causal behavior and strength/exposure gates in focused fixtures. Only broaden replay if it changes the intended behavior and clears those gates.

## One module and interface

`ResponseController.step(sample, authority)` consumes one causal producer sample and the latest same-owner consumer authority receipt. It returns the selected acceleration request, integral update diagnostics and support/fallback status. No baseline output, reference I, future torque, copied recorded integral or recorded counterfactual response is accepted.

A sample contains monotonic timestamp/sequence/epoch, target acceleration, measured acceleration and speed, phase, CAN/pose/target validity, pedals, shouldStop and FCW/force-decel. An authority receipt contains original consumer timestamp/sequence, actual commanded brake/precharge, valid-propulsion flag and numerical command when valid, ordinary clearance state and fresh received torque. The existing observer remains independent and authoritative; this module cannot clear it, alter its clock, or suppress its fault.

Internal states:

| State | Known authority | Integral semantics |
|---|---|---|
| Friction / stop | Signed brake request; measured response still lagged | Native signed acceleration-error integration; immediate urgent/stop/strong path |
| Pending release | No propulsion permission; received pressure not clear | No numerical use of −5; existing signed/no-authority semantics, unchanged timeout and distinct-clear checks |
| Qualified propulsion ramp | Valid numerical propulsion, independent measured clearance already established | Native acceleration-error term plus bounded tracking correction toward actual selected valid numerical command |
| Settled drive | Valid numerical propulsion and selected command equals requested command | Tracking correction exactly zero; native measured-error integration |
| Unsupported / invalid | Unknown authority or stale/foreign/invalid receipt | Exact installed fallback; no prediction of coast force or clearance |

The initial implementation varies only qualified valid-propulsion ramp behavior. It does not introduce a new no-brake/inactive-propulsion allocator mode. It tests whether correcting a known numerical authority mismatch changes the harmful producer/allocation response without needing an unobserved coast model. This is distinct from freezing an entire ramp: the correction is proportional to an actual same-clock selected-command residual and vanishes at equality.

## Causal integral law and measured error

Let `e_a = a_target − a_measured`. The controller keeps its own issued-request cache keyed by epoch/producer sequence, containing its actual returned request and target timestamp. `u_issued` is that exact consumed request, and `u_selected` is the valid numerical propulsion command returned by the qualified ramp for the same consumed sequence. Both are net acceleration requests in the same PCM convention; neither is pitch-adjusted brake-bit demand. Compare no receipt to the current target-plus-I value. The cache contains candidate-issued commands, never recorded/reference I. Native clipped PID integration supplies `ΔI_native`; native freeze/limits remain the reference mechanism outside the selected state.

In a qualified ramp only, propose `ΔI_track = dt_receipt * k_track * (u_selected − u_issued)`, clipped to the actual available native integral headroom and a fixed finite per-update correction limit. This is a derivative update, not an I reset or a reference-I copy. The correction is admitted only when the same causal receipt establishes `0 <= u_selected < u_issued` and the measured acceleration error is nonpositive (actual acceleration is at least target) and the continuous current-ramp measured speed error is nonpositive (no accumulated underspeed). A below-target acceleration or positive accumulated speed deficit inhibits negative tracking immediately. This prevents reducing demand merely because a ramp exists while the vehicle is already accelerating too slowly. These conditions are necessary admission checks, not proof that lower demand cannot later retrigger the grade selector. A correction consumes each distinct receipt once, with strictly increasing same-owner sequence and consumer clock, receipt age <=100 ms, causal issue-before-consume-before-now ordering, and a receipt interval >0 and <=100 ms. Repeated receipt publications cannot spend the correction twice. A changed target timestamp invalidates the tracking episode until a receipt for the current target arrives; it does not reset I, clearance, or any weak-demand account. Existing nonzero CommandRecovery overlays are out of scope to avoid double correction. Invalid clocks/owner or urgent context use installed fallback. No valid command is treated as proof that its requested acceleration was physically achieved. A research gain of 1/s and per-step correction limit .001 m/s² are proposed for the first hypothesis, not tuned to achieve edge counts; failed focused gates reject the hypothesis rather than changing these constants repeatedly.

Maintain `e_v = integral(a_target − a_measured) dt` only over continuous qualified samples, with explicit invalidation on owner/clock/target gaps. This is actual measured tracking error relative to the consumed target trajectory, not planner vehicle speed and not measured road-grade truth. It is an overshoot/undershoot admission gate and diagnostic in this initial implementation, not a fresh deferral allowance. A new target/invalid receipt ends the diagnostic ramp interval; it cannot forgive integral, clearance or the installed demand-area account. Existing sampled weak-demand .01/.3 debt remains untouched; actual-error diagnostics cannot reset or rearm it.

This is a numerical command-authority anti-windup hypothesis; it does not identify achieved-acceleration dynamics. The actual-error/speed-error record is diagnostic in this first spike, not a claim to have resolved that missing physical model. The expected material effect is a reduction of ramp request/integral excess while command authority is lower, followed by continuous return to native integration when selected equals wanted. This may fail the full-brake/exposure or later strong-braking gates: reducing ramp I can reenter braking sooner. That is an explicit rejection condition, not an acceptable trade for a prettier trace.

## Physical model contract

A separate injected plant adapter exists only in hypothetical closed-loop tests. It models valid net-command lag, brake actuation/release, grade disturbance and measured feedback delay, with declared parameters and finite uncertainty sweeps. These parameters are not fitted Alpha coast dynamics. Test controller causality, anti-windup direction, transition continuity and recovery under delayed observations; do not report synthetic smoothness as observed road improvement.

The saved 374/516/531/125/359/512 evidence can constrain conditional gear, RPM, status, torque and settled acceleration relationships. The missing NEW model capability remains held-out dynamic transitions, unsupported Alpha no-brake/inactive-propulsion, and integrated authority/I effects after the mode ends. No numerical coast prediction is admitted from the old settled table. Unknown dynamic support is explicit and falls back to installed behavior.

## Validation and stop conditions

1. Test-first actual native PID/consumer fixtures: a fresh same-owner ramp with valid selected/request mismatch changes I causally; equality does nothing; −5/stale/foreign/fault/pedals/stop/urgent/strong contexts cannot admit correction. Preserve native limits and reset lifecycle. No observer or deficit-account mutation is possible through the interface.
2. Synthetic closed-loop tests: delayed valid-propulsion ramp, release followed by strong braking, grade disturbance and stale observations. Vary plant delay/lag, disclose hypothetical assumptions, and compare actual tracking error, integral excess, brake exposure and urgency response. Reject if the causal response is unstable or depends on unavailable future state.
3. Focused saved full-route fixtures first, with actual LongControl/CarController feedback: named session08 three windows, city, latest first-gear restart, original highway and prior later-strong-demand regression. Compare every callback and encoded strong demand; no lost activity, changed fault/clearance history, new gas conflict, extra full-brake exposure or weaker strong/weak braking is tolerated. Benefit must be nonzero in the intended response/target metric; mere baseline identity is compatibility.
4. Only if focused benefit and all protected gates pass: fresh full 316-segment candidate against exact-source verified saved baseline; fresh native replay afterward. Otherwise preserve the failed candidate and report the exact failure. Do not spend another full replay on a known focused failure.

This first hypothesis deliberately avoids new coast authority. If actual ramp tracking fails the protected gates, it establishes that command tracking alone cannot resolve the joint blocker. Reassess the design around the missing dynamic/achieved-authority evidence rather than adding accounts, widening thresholds or making a second unobserved coast bridge.

## First counterexample and joint amendment for review

The first numerical-only implementation passes seven causal/error-admission tests but fails the grade-mode counterexample before any replay: issued raw .3000 plus effective gravity −.2995 is a valid positive .0005 net request. The permitted −.001 tracking increment changes it to −.0005 and requests a new friction entry, even though actual acceleration .3 is above target .2 and measured accumulated speed error is nonpositive. Actual-error admission alone is therefore insufficient. No gain change or full replay is justified; preserve this failed spike.

Proposed joint revision: the allocator returns a **propulsion-mode feasible command interval**, distinct from achieved acceleration. It is derived from the existing bit-selection/release semantics and its causal effective-grade estimate, not a fitted coast force. The producer projects tracking into the intersection of native integral limits and the current/receipt same-convention mode interval, so tracking cannot itself command a crossing into friction. The interval must be sourced from candidate consumer state and current causal pose, with owner/sequence/pose freshness checked; it is not a recorded baseline-output oracle. If the current/receipt estimates disagree or a valid conservative interval cannot be established, skip tracking and retain installed behavior. No threshold is widened, no debt is reopened, and strong/stop/FCW bypass projection immediately.

The specific invariant is `u_after_tracking >= max(current_mode_floor, receipt_mode_floor)` whenever a valid propulsion ramp is deliberately retained. The floor uses the existing positive-release margin in the same net acceleration convention. This describes command feasibility, not physical achieved authority. A causal grade change after the producer sample may still alter consumer feasibility; the consumer must reject/cancel any retained-mode assertion outside its own current feasible interval rather than trust the producer's stale floor. That cross-clock behavior requires its own tests and focused coupled replay, and may expose a need for a genuine allocator protocol seam rather than another producer-only patch.

Parent review requested before implementing this amendment. The unresolved physical dynamic model remains explicitly unsupported.

### Revised interface: optional correction transaction

`propose(sample, receipt, current_native_request, current_mode_predicate)` returns an optional **negative command correction** projected into the present command-mode feasible interval. The exact already-released propulsion predicate is net request >=0, not a permanent +.02 floor. If the native request itself is outside that mode interval, do not project it upward: return no correction and allow installed necessary braking.

The candidate stores its own native and corrected issued command alternatives with epoch/sequence/target/pose clocks. The consumer rechecks the optional correction using its newer causal grade/pose and installed mode predicate. If the correction alone would create a friction crossing, it vetoes **only that optional correction** and evaluates the current issued native request through the unchanged installed allocator. Native negative demand remains negative; there is no floor-driven boost and no override of needed braking. The standard numerical request/authority receipt describes the command actually selected. Local research metadata identifies whether the proposed correction was applied; it does not fabricate achieved acceleration or torque.

The integral correction is staged until an exact matching same-owner receipt acknowledges the corrected branch. Only then is that derivative contribution committed once to the candidate's current integral. A veto discards an uncommitted proposal, not a previously committed integral or counterfactual I. Target/clock/owner/urgent invalidation discards pending optional work and uses the installed native path; it never restores or resets committed I. Permit at most one outstanding correction transaction, with finite stale expiry and exact sequence/clock matching, so repeated publications or reordered acknowledgements cannot apply it twice. The own issued cache explicitly contains both candidate-generated branches; neither is recorded baseline output. The physical effect of an earlier applied but subsequently superseded uncommitted command remains an observed-response matter, not silently undone in history.

This transaction makes consumer-newer-grade disagreement testable without allowing an older producer floor to suppress necessary braking. It still cannot guarantee that a previously committed correction leaves later I/fault/brake history unchanged; that remains a decisive focused regression gate.
